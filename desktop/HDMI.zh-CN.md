# HDMI 内核修复与旧配置迁移

`v0.2.2-t5` 的 CLI、XFCE / LightDM、KDE / SDDM 共用 HDMI 内核补丁，替代 v0.2.1 的桌面启动恢复脚本。SD 和 UFS 使用同一修复，不指定显示器型号、分辨率或刷新率，也不强制 HPD 连接。

## 修复了什么

原 T5 BSP 在检测到 HDMI 拔出时，直接关闭发送端并清空私有模式状态，却没有同步更新 DRM 已提交的活动 CRTC。显示器锁定时的短暂 HPD 变化也会进入该路径；重新连接后若客户端没有再次提交模式，就可能留下「软件仍认为正在显示，硬件输出已经关闭」的状态。

补丁从 HPD 拔出路径移除上述关闭和清空动作，让原有 DRM atomic enable / disable 和电源管理回调负责输出状态。真实 HPD 检测、50 ms 再采样、连接通知、EDID 与 CEC 缓存失效仍保留，桌面仍能收到拔插通知并自行提交模式。源码与构建输入见 [内核补丁说明](../kernel/hdmi/README.md)。

这是 CLI 和桌面共用的驱动层修复；没有新增 GPU 渲染或视频硬件解码能力，也未修改 USB。

## 验证范围

此前当前 CLI 测试机使用同一补丁，在 `hpd_mask=0`、旧兜底禁用的条件下完成两次启动和一次同一显示器的实际 HDMI 拔插，用户均确认画面正常，拔插后自行恢复。随后移除了该测试机上的 CLI 兜底服务和脚本。

**v0.2.2 的新软件包、六张新镜像以及 KDE / XFCE 没有运行新的自动化、滚动升级或实机测试。** CLI 上的既有结果不能作为新桌面镜像已通过验收的结论。

补丁未覆盖所有 HDMI 问题：

- CLI 不会因此获得完整的显示器更换与自动模式选择能力；不同接收端、无屏启动后再连接、需要重新设置 SCDC 的场景尚未验证。
- 休眠恢复没有新增修复或测试。
- 移除原 HPD 关闭函数，也移除了其中隐含的 HDCP disable。CLI 验证没有使用 HDCP；受保护视频在断连、换接收端后的认证和重新认证仍需单独处理与验证。
- 原 BSP 的 EDID 缓存并发问题不在本补丁范围内。

## 旧桌面配置如何迁移

`radxa-a7z-base 0.1.0-6` 依赖 `linux-radxa-a7z=6.6.98_4-2`。它不再打包 `/usr/bin/a7z-hdmi-compat`，并通过 `92-a7z-hdmi-migrate.hook` 在安装或升级后运行一次配置清理；新镜像构建还会再次执行严格清理。

处理范围仅为：

| 路径 | 迁移行为 |
|---|---|
| `/etc/lightdm/lightdm.conf.d/95-a7z-hdmi-compat.conf` | 移除旧项目启动 / 停止命令 |
| `/etc/sddm.conf.d/95-a7z-hdmi-compat.conf` | 移除旧项目 DisplayCommand / DisplayStopCommand |
| 上述两个路径的 `.disabled` 副本 | 同样清理，避免以后重新启用旧命令 |
| `/usr/bin/a7z-hdmi-compat` | 普通升级由 pacman 移除旧包文件；离线遗留文件只在 SHA256 匹配原版时删除 |

精确匹配项目默认内容的 95 配置会删除；有用户增补时，只移除原样的旧项目命令行，其余设置保留。未知旧命令、修改过的离线 helper 或符号链接会保留并报告，构建模式遇到这些情况会停止，要求先人工处理。已有用户自定义显示脚本不会被替换为项目默认值。

`70-a7z-desktop.conf`、PowerVR Xorg / Vulkan 设置和原 SDDM 系统 Xsetup / Xstop 文件保持原样。删除项目 95 覆盖后，未另做自定义的 SDDM 回到自己的默认 Xsetup / Xstop。清理入口不访问 HPD sysfs，不重启正在运行的显示管理器；更新后应重启进入新内核，原运行会话中已设置的 HPD 兜底随重启消失。

自行复制到其他位置的旧脚本、CLI 实验服务或其他强制 HPD 设置不属于发行包管理范围，需要自行移除。升级方法见 [滚动升级说明](../ROLLING-UPGRADE.zh-CN.md)。

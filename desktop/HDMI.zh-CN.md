# HDMI 桌面启动恢复

`v0.2.1-t5` 为 XFCE / LightDM 和 KDE / SDDM 增加显示管理器启动钩子，用于显示器已连接、X11 已有活动模式，但厂商驱动实际输出仍关闭的情况。逻辑适用于满足状态条件的 HDMI 显示器，**不筛选型号、不固定分辨率或刷新率，也不对所有显示器无条件强制连接**。

本版按要求直接修复、打包和发布；新增的通用判断逻辑和六张新镜像均未运行自动化测试、滚动升级回归或实机启动。此前单款显示器的排查结果不等于本版已完成多型号适配验证。

## 启动时如何处理

钩子读取连接状态、有效且校验和正确的 EDID、Xrandr 模式和厂商输出状态。优先保留 Xrandr 标记为当前的模式与刷新率（`*`）；没有当前模式时，采用显示器优选模式（`+`）。它不会覆盖 EDID，也不会生成固定的通用分辨率。

处理按下列顺序进行，总时间有上限：

1. 先观察约 4 秒。正常输出不更改，正常 HPD 热插拔检测保留。
2. 若连接与 EDID 保持一致，X11 有活动模式，而厂商 `[drv state]` 持续为「时钟开启、输出关闭」，先普通关闭 / 重新启用 HDMI，使用选定的模式与刷新率。
3. 普通恢复后再观察约 4 秒；同一异常仍持续时，才通过厂商 `hpd_mask` 接口写入明确的十六进制 `0x11`，保持 HPD 连接，并再次启用输出。

没有当前模式时可以普通启用优选模式，但不会仅因无当前模式就强制 HPD。未知接口、无有效 EDID、断开连接或 HPD 已由其他配置管理时，不强制处理。SDDM 原有 Xsetup / Xstop 脚本仍由钩子衔接，显示管理器提供实际的 X11 显示与认证环境。

## 范围与限制

这个处理针对的是**显示管理器启动窗口内**的输出状态不一致，没有修改 BSP 内核、设备树或启动器，不代表 HDMI 根本问题已经修复。它不能覆盖所有「无信号」原因，也不保证开机之后的插拔、切换器操作或休眠恢复会自动修复。应在登录界面启动前接好显示器。

仅当强制 HPD 兜底生效时，该 HDMI 连接的自动热插拔检测才会受限；此时拔掉或更换显示器，系统可能继续保留此前的模式。显示管理器停止时会尝试释放本钩子设置的 HPD 状态，重启也会恢复内核初始检测，再由钩子重新判断。需要频繁切换显示器而又触发兜底时，可按下文停用该配置。

配置由 `radxa-a7z-base 0.1.0-5` 提供，图形镜像依赖 `xorg-xrandr`。DP 输出和 CLI 镜像不启用此处理，本版没有 USB 修复。

## 配置位置

| 文件 | 作用 |
|---|---|
| `/usr/bin/a7z-hdmi-compat` | 共用的 HDMI 兼容入口 |
| `/etc/lightdm/lightdm.conf.d/95-a7z-hdmi-compat.conf` | XFCE / LightDM 的启动、停止钩子 |
| `/etc/sddm.conf.d/95-a7z-hdmi-compat.conf` | KDE / SDDM 的启动、停止钩子 |

显示管理器提供当前 X11 的显示与认证环境。请通过正常的图形启动流程应用配置，不要复制旧会话的 `XAUTHORITY` 路径，也不要沿用旧 `xrandr` 模式 ID。SDDM 原有的系统 Xsetup / Xstop 脚本仍由钩子衔接。

## 关闭与恢复

默认仅在异常持续、普通恢复无效时才强制 HPD。若希望完全关闭自动恢复及其 HPD 兜底，先按所用桌面停用对应配置。下面只执行匹配当前环境的一组命令；不要对不存在的另一种桌面配置操作。

XFCE：

```sh
sudo mv /etc/lightdm/lightdm.conf.d/95-a7z-hdmi-compat.conf \
  /etc/lightdm/lightdm.conf.d/95-a7z-hdmi-compat.conf.disabled
```

KDE：

```sh
sudo mv /etc/sddm.conf.d/95-a7z-hdmi-compat.conf \
  /etc/sddm.conf.d/95-a7z-hdmi-compat.conf.disabled
```

保存工作后自行重启，启动恢复将停用，HPD 使用内核默认检测。重新启用时，把对应 `.conf.disabled` 改回 `.conf`，在下次启动前接好显示器。更改前请检查是否已存在同名备份文件，避免覆盖自己的配置；重新安装基础包后也应核对配置是否恢复。

## 排查依据与本版边界

此前两块 A7Z、SD XFCE 与 UFS KDE 的排查中，用户在同一款 P27QBA-RA 显示器上确认过：保持 HPD 连接并重新启用原生模式后，物理画面恢复。早期只针对该型号的本机 SDDM 钩子也曾获用户确认开机显示正常。这些记录促成了此次按状态、动态模式进行恢复的方案，**不是新增通用逻辑或其他显示器的测试结果**。

[锁定的厂商源码](https://github.com/radxa/allwinner-bsp/blob/f51e1e6195d4350abc590bff852e213279e660a6/drivers/drm/sunxi_drm_hdmi.c)中，断开路径会清除 DRM 模式状态并关闭输出；重新连接路径读取 EDID、更新 HDCP 支持，随后发出热插拔通知，输出重启还依赖后续的 DRM 操作。既有故障记录出现过 HPD 已重新连接而输出仍关闭。本版以这一可观察到的状态异常为恢复条件，没有确定所有 HPD 变化的物理原因。

内部屏幕截图、Xrandr 的 connected 状态或发送端 PLL 锁定都不能单独证明物理显示器实际有画面。本版未重复开展现场测试；测试范围与构建来源见 [发行说明](../RELEASE.zh-CN.md)。
